# Olve.TypeSpec + @olivervea/typespec-csharp

Spec-first HTTP APIs for C# services. Source: `Olve.Utilities/src/Olve.TypeSpec/` (runtime, NuGet) and `Olve.Utilities/src/typespec-csharp/` (emitter, npm). READMEs: [runtime](../../../src/Olve.TypeSpec/README.md), [emitter](../../../src/typespec-csharp/README.md).

## Shape

```
spec/main.tsp ── tsp compile ──► artifacts/generated/<Prefix>{Models,Api,JsonContext}.g.cs ──► compiled into the service
                            └──► openapi.json ──► clients (Hey API, …)
```

`<Prefix>` is the service namespace's name (`namespace Widgets;` → `WidgetsApi`, `AddWidgetsApi`, …) unless `prefix` is set. The generated code relies on `Olve.TypeSpec`: `IOperationHandler<TRequest, TResponse>`, `IOperationResponse`, `ApiOperation`, `IApiErrorWriter`, `RequestValidation`, the binding-failure middleware, `JsonResponse<T>`, `IServerSentEvent` / `ServerSentEvent<T>` / `ServerSentEventsResult<T>`, `TypeSpecApiExtensions`.

## Rules

1. **The contract holds only what's built.** Add a field, status or operation in the change that implements it.
2. **One handler class per operation**, implementing the generated `I<Group><Op>Handler`; it returns a variant of the generated response union (`new XResponse.NotFound(error)`, or the success body itself for an implicit `Ok`). Expected failures are declared responses, never exceptions.
3. **The app owns its error body**: a spec model mapped with `external-types`, plus one `IApiErrorWriter` registration that answers binding and validation failures (typically the body when `operation.Declares(status)`, else the bare status).
4. **Wire it with the generated methods**: `services.Add<Prefix>Api()`, register handlers and the error writer, then `app.Use<Prefix>Api()` (fails fast on a missing handler) which returns the route builders for app-side conventions (`endpoints.WidgetsGet.RequireAuthorization("read")`).
5. **Generated files are not source**: a gitignored `artifacts/` folder, regenerated by an MSBuild target or a build step; never edit them.
6. **Don't re-test the generator.** Route coverage, schema conformance and status rules are proven by the conformance suite in Olve.Utilities; a service tests its own behaviour over HTTP.

## Emitter options (`tspconfig.yaml`)

| Option | Meaning |
| --- | --- |
| `namespace` | C# namespace of the generated code (default `Generated.Api`). |
| `prefix` | Prefix of generated file and type names: `<prefix>Models.g.cs`, `<prefix>Api`, `<prefix>Operations`, `<prefix>Endpoints`, `<prefix>JsonContext`, `Add<prefix>Api`, `Use<prefix>Api`, `Map<prefix>Api` (default: the service namespace's name). |
| `external-types` | Spec model name → existing C# type, not generated (the error envelope, shared models). |

## Supported / reported

Supported (all exercised by the example contract above): models with `@visibility` splits, enums (string by wire value, numeric), `@discriminated(#{ envelope: "none" })` unions, arrays, `Record<T>`, nullables and optionals, path/query/header parameters, `@query(#{ explode: false })` string lists, several success statuses, SSE streams of an `@events` union whose variants carry `type: "<event name>"`, request-body constraints (`@minLength`, `@maxLength`, `@minItems`, `@maxItems`, `@minValue`, `@maxValue`).

Reported as `unsupported-*` warnings, emitted as `JsonElement` or skipped, never silently mistyped: untagged unions, enveloped discriminated unions, cookie parameters, multipart bodies, status code ranges, array parameters other than `explode: false` string lists in the query. `src/typespec-csharp/test/fixtures/unsupported.tsp` holds one operation per shape and the snapshot test asserts each diagnostic. None is blocked by the design; each can be added when a contract needs it. Validation covers the top-level request body only; `@pattern` is not enforced.
